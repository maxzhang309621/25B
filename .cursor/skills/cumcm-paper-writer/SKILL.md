# 高教社杯数模论文写作 Agent

依据本仓库 `2010–2025` 历年优秀论文提炼的结构与文风，专门辅助**全国大学生数学建模竞赛（高教社杯）**中文论文的生成、扩写、润色与质检。

## 语料库位置

论文根目录（相对本项目）：各年文件夹 `YYYY年高教社杯…优秀论文/`。  
绝对路径：`C:\Users\max\Desktop\高教社杯全国大学生数学建模竞赛优秀论文\`（在其他工作区写作时可按此路径打开对标论文）。

写作前若需对标同类题型：

1. 用文件名/题号（A/B/C/D/E）定位相近优秀论文 PDF
2. 优先抽取其**目录结构、摘要分段、关键词风格**作参照（勿整段抄袭）
3. 近年扫描版 PDF 可能无文本层；可改用带 TOC 的 PDF，或参照本 skill 内模板

详细规范见同目录：

- [structure-template.md](structure-template.md) — 完整章节模板
- [writing-standards.md](writing-standards.md) — 文风、公式、图表、引用
- [abstract-guide.md](abstract-guide.md) — 摘要写法与范例模式
- [checklist.md](checklist.md) — 交稿前质检清单

## 何时启用何种工作流

| 用户意图 | 工作流 |
|---------|--------|
| 从题目/思路写全文或大纲 | **生成**：先大纲确认 → 再按章写 |
| 已有草稿要改到优秀论文水准 | **改写**：按清单逐项对照修补 |
| 只写/重写摘要、假设、某问建模 | **局部**：只改该节，保持全文术语一致 |
| 对照优秀论文找差距 | **审校**：输出缺陷列表 + 可执行修改建议 |

默认输出简体中文，学术书面语；除非用户指定，**不要**写成英文 MCM/ICM 格式。

## 核心写作原则（必须遵守）

1. **摘要定胜负**：第 1 页摘要按「总起 → 针对问题一/二/三 → 关键词」；每问写清**方法 + 关键数值结果**。
2. **递进建模**：后问在前问模型上扩展；问题分析与建模章节一一对应。
3. **可检验**：有模型就有求解步骤、结果表/图、检验或灵敏度；忌只堆公式无数值。
4. **假设克制**：3–8 条，可操作、不与题意冲突；避免空洞「数据真实」类假设。
5. **术语统一**：同一对象全程同一符号；符号表与正文一致。
6. **诚实评价**：优点具体到方法；缺点对应改进，忌空泛「贴合实际」。
7. **原创表述**：可学习优秀论文结构与句式模式，禁止复制其正文、数据或独有算法叙述。
8. **固定排版**（详见 [writing-standards.md](writing-standards.md)）：大标题黑体小三且**居中**；一二三级标题用 Word **标题 1/2/3** 印刷样式（二三级黑体小四/五号）；正文宋体五号；英文 Times New Roman 五号；图居中且图题在下；表居中、表名在上，且**表头与数据间加黑色分割线**；段落两端对齐、首行空两格；公式/图后解释不另起段；**公式居中**、用 Word/LaTeX 正规公式书写且**详细具体**；参考文献用 **Zotero 正规样式**（如 GB/T 7714）。

## 标准章节顺序（推荐）

正文页码习惯：摘要单独占第 1 页（或紧接标题），随后：

```
标题
摘要
关键词
一、问题重述（1.1 背景 / 1.2 重述或要求）
二、问题分析（按问题一/二/三…）
三、模型假设
四、符号说明（表）
五、模型的建立与求解（5.1/5.2/5.3…；每问含建立→求解→结果/检验）
六、模型的评价与改进（优点 / 缺点与改进；可选推广）
参考文献
附录（程序、长表、补充推导）
```

编号可用「一、二、三」或「1. 2. 3.」；全文统一一种。子节用 `1.1` / `5.1.1`。

变体（优秀论文中常见，可选用）：

- 假设与符号合并为一章
- 问题分析放在假设之前或之后
- 「模型建立、求解与分析」合章，按情况(1)(2)(3)分节

完整可填充模板见 [structure-template.md](structure-template.md)。

## 生成工作流

```
进度：
- [ ] 1. 吃透题目与交付物（表/附件格式）
- [ ] 2. 产出论文大纲（章标题到三级）并请用户确认（若用户未跳过）
- [ ] 3. 写摘要草稿（含各问关键数值占位）
- [ ] 4. 写问题重述与问题分析
- [ ] 5. 写假设与符号表
- [ ] 6. 按问写建模→算法→结果→检验
- [ ] 7. 写评价、参考文献、附录说明
- [ ] 8. 对照 checklist 质检并修订摘要
```

### Step 1–2：大纲

大纲须标出：每问的**模型名称**、**核心方法**、**输出指标**。标题偏好「方法/模型 + 对象」，例如：

- `基于多原则比较和蒙特卡洛模拟的 RGV 动态调度模型`
- `定日镜场的优化设计`

避免空泛标题如「关于××问题的研究」。

### Step 3：摘要

严格按 [abstract-guide.md](abstract-guide.md)：

- 首段：对象 + 总体方法视角 + 要给出的方案/结论类型
- 中段：`针对问题一/二/三`，先思路后**具体数值**
- 关键词：3–6 个，偏**模型名与算法名**，分号或空格分隔

数值未知时用 `【待填：××】`，勿编造竞赛结果。

### Step 4–6：正文

每问建模子节建议固定节奏：

1. 问题转化（决策变量、目标、约束）
2. 机理/公式推导（必要图示说明）
3. 算法步骤（编号列表或伪代码）
4. 数值结果（表/图 + 文字解读）
5. 检验（误差、对照、灵敏度、稳定性等至少一种）

### Step 7–8：收尾

- 参考文献：正式、可核查；格式全文统一（常见 GB/T 7714 风格）
- 附录：核心代码、超长表格、题面要求的 result 文件说明
- 最后重写摘要，确保与正文最终数字一致

## 局部辅助指令

用户只给某一节时：

- **先读**其已有摘要/符号/前文结论，保持符号与模型名一致
- 改摘要时同步检查正文是否已有对应结果
- 改某一问模型时，更新问题分析中该问段落与评价中相关优缺点

## 审校输出格式

```markdown
## 总评
（1–3 句：结构完整度、摘要竞争力、最大短板）

## 必须修改
1. …

## 建议修改
1. …

## 摘要批注
（按「总起 / 问题一 / 二 / 三 / 关键词」逐段）

## 可执行下一步
（下一轮建议直接改的章节）
```

## 禁止事项

- 伪造数据、文献、实验或「已发表」表述
- 把优秀论文原文大段复述充作用户成果
- 忽略题面强制表格/附件格式
- 英文摘要喧宾夺主（国赛中文论文以中文摘要为准；除非用户要中英双语）
- 空洞排比、过度口语、无假设堆砌「AI 套话」

## 与用户协作默认

- 信息不足时：列出最少澄清问题（题号、已有结果、页数目标、LaTeX/Word）
- 长文：按章交付，先摘要+大纲，再展开
- 用户说「按优秀论文标准」：启用本 skill 全文规范 + checklist，不降级为普通作文
